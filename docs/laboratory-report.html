1. Problem and Requirements

This project implements a FreeRTOS-based room-monitoring system for an STM32F103C8T6 Blue Pill. The system measures temperature, humidity, relative ambient light, and motion. It displays one selected measurement, accepts rotary encoder navigation, activates a buzzer outside the 18.0 C to 30.0 C normal range, and changes between ACTIVE and INACTIVE activity states.

Simulation platform: PlatformIO with STM32Cube and native FreeRTOS APIs, simulated in Wokwi using a DHT22, photoresistor, PIR sensor, KY-040 rotary encoder, SSD1306 OLED, and buzzer.

Figure 1. Hardware and peripheral architecture.

Hardware initialization is performed in main(). The application entry point app_main() creates the queues, event group, mutex, and six tasks before starting the scheduler. The OLED is owned by DisplayTask, while sensor acquisition, input, motion, alarm, and state management have separate task responsibilities.

vTaskDelayUntil() is used for periodic sensor and display execution. The queue objects carry sensor data, navigation commands, and the latest motion state. The serial mutex protects shared diagnostic output. EVENT_ALARM_BIT2 is set by AlarmTask when temperature is outside the normal range and cleared when it returns to normal.

4. Implementation

SensorTask validates DHT22 readings, copies the latest PIR state from xMotionQueue, and scales the ADC reading to a relative 0-100% light value. DisplayTask displays the selected measurement together with STATE: ACTIVE/INACTIVE and ALARM: ACTIVE/NORMAL.

AlarmTask evaluates the latest sample every 100 ms and controls a 1 kHz TIM1 PWM signal on PA8. Alarm thresholds, navigation, and state transitions are separated into testable logic functions.

7. Engineering Discussion

Latest-value queues are appropriate because consumers need the current sensor and motion state rather than a historical stream. The OLED has a single owning task to avoid competing I2C transactions. The event group provides shared activity, motion, and alarm status signals.

The LDR value is relative rather than calibrated lux. Wokwi behavior may differ from physical hardware. The remaining verification work is to record the Wokwi functional tests, complete the deliberate FreeRTOS fault experiments, and capture final screenshots.

8. Conclusion

The project demonstrates a modular STM32 FreeRTOS architecture with six cooperating tasks, queues, an event group, a mutex, periodic scheduling, a state machine, hardware PWM, and host-based decision-logic tests. The design separates hardware access from deterministic logic and provides a foundation for further physical-hardware testing.
